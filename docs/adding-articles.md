# 新しい記事を追加する

`Article` は [src/content.ts](../src/content.ts) の `ARTICLES` 配列に、
所有ユーザーは [src/users.ts](../src/users.ts) で管理する。既存記事
（例: `professions-transport`, `professions-food`）を雛形にコピーするのが早い。

## 1. テーマとレベルを決める

- **シリーズを揃える**: 例のシリーズ「〜を支える人たち」は intro → 3グループ
  （導入・展開・応用の順）→ closing、という段落構成で統一している。
- **語数と難易度**: 既存記事は本文 200–250 語程度、注釈 25–35 語、
  クイズ 8 + 8 問。JLPT N4〜N3 が目安。
- **重複チェック**: 既に紹介した職業・語彙は極力ずらす（例: `professions-daily` で
  出た「医師」「先生」は `-transport` `-food` では出さない）。

## 2. 本文を書く

- 段落は空行区切り。1段落に1グループ（3〜5文）。
- 1文1トピック。読点でつなぎすぎない。
- 導入・結びは「私たちが〜のは、〜のおかげです」型で開き、「こうしてみると〜
  支えられているんですね」型で閉じるとシリーズ感が出る。
- 固有語（職業名や食材名）はカタカナ／漢字を極力そのまま出す。
  クイズ・注釈がそこに掛かる。

## 3. `Article` を組み立てる

`src/content.ts` の末尾に追記する。フィールド定義は同ファイル冒頭
[src/content.ts:53](../src/content.ts#L53) を参照。

```ts
{
  id: "professions-food",           // kebab-case、ユニーク
  title: "食を支える人たち",
  subtitle: "畑・海・お店で働く仕事",
  date: "2026-08-29",               // YYYY-MM-DD、サイドバー順で使う
  text: `私たちが毎日ごはんを…

まず、…

次に、…

最後に、…

こうしてみると、…`,
  annotations: { /* §4 */ },
  translations: { /* §5 */ },
  quiz: { cloze: [ /* §6 */ ], reading: [ /* §6 */ ] },
},
```

## 4. 注釈 (`annotations`)

キーは辞書形（`base`）または連続する複数トークンの表層形。kuromoji が
分割してしまう複合語（例: `畜産農家`）は表層形で書けば1語として扱われる。

- 助詞・活用語尾など「教材上の重要度が低い語」は書かない（kuromoji が
  読みだけ自動で付ける）。
- 重要度の高い語 25〜35 個を選ぶ。動詞は基本形（例: `育てる`）。
- 意味は英語のセミコロン区切り、`pos` は日本語（`名詞`, `動詞（一段）`,
  `名詞・する動詞` など）。
- `note` にニュアンス・用法・類義語との違いを日本語で1〜2文。
- `examples` は必要な語だけに1件。文と英訳のペア。

```ts
農家: {
  reading: "のうか",
  pos: "名詞",
  meaning: "farmer; farm household",
  note: "米や野菜、果物などを畑や田んぼで作る仕事の人。",
  examples: [
    { ja: "この村には米を作る農家が多い。", en: "There are many rice-growing farmers in this village." },
  ],
},
```

## 5. 文訳 (`translations`)

キーは**句点まで含む正確な1文**。差異があるとマッチせず、翻訳練習タブ・
文末の「訳」ボタンで表示されない。本文をコピーして、句点で区切ったものを
そのままキーにする。改行やスペースを混ぜないこと。

- 訳は直訳ではなく自然な英語。読者が「日本語で言うと何て言うか」を
  逆引きしやすいように、日本語の情報単位を維持する。
- 会話的な語尾（〜ね、〜んです）は英訳でも軽い口語（"you know", 疑問文の
  形など）で受ける。

## 6. クイズ (`quiz`)

**穴埋め (`cloze`) — 8問推奨**

- 各記事の主要語（`annotations` に入れた新出職業・道具など）を1問ずつ。
- `options` は 4 択。誤答は同じ記事内の別の職業を混ぜて紛らわしくする
  （例: 「農家」の問題に「漁師」「料理人」「栄養士」）。
- `explanation` は1〜2文で「なぜその答えか」を書く。

```ts
{
  before: "米や野菜、果物を畑や田んぼで育てるのは、",
  after: "です。",
  options: ["漁師", "農家", "料理人", "栄養士"],
  answer: 1,
  explanation: "「農家」は畑や田んぼで作物を育てる仕事です。",
},
```

**読解 (`reading`) — 8問推奨**

- 事実確認 4〜5 問（「〇〇はどんな仕事？」）、比較 1〜2 問
  （「A と B の違いは？」）、応用 1〜2 問（「もし〜がいなかったら？」
  「順を追って説明してください」）の配分がバランスが良い。
- 模範解答は本文の語彙内で書く。新規語彙は入れない（読者は本文を
  読み終えた状態で答える想定）。
- `hints` は「模範解答に出てくる主要語」を並べる。読者が自力で書く
  ときの語彙ヒント。

**文法選択 (`grammarChoice`) / 助詞穴埋め (`particle`) — とびら利用者（Artem）向け、各 8 問目安**

`tobiraCurrent` が設定されたユーザーには「文法選択」「助詞クイズ」タブが出る。

- 文法選択: 英訳を読んで、日本語文の空欄に入る文法形を 4 択で選ぶ。
  `before + options[answer] + after` が本文の1文と一致するように作る
  （テストで確認）。誤答は同じ課の別の文型を混ぜる。`grammarKey` を付けると
  回答後に「📘 文法」ボタンでとびらの解説が出る。
- 助詞穴埋め: 本文の1文の助詞を `［を］` のように全角角かっこで囲む。
  1文に 2〜5 個。括弧を外した文が本文と一致すること（テストで確認）。
  選択肢は共通の助詞セット（は が を に で と へ も の から まで より）で、
  セット外の答え（`や` など）は自動で追加される。
- どちらも `explanation`（文法の説明）は**簡単な英語**で、1〜2文に短く書く。日本語の例文・文型は
  そのまま混ぜてよい（ふりがなが付く）。単語クイズの解説は日本語のまま。

```ts
grammarChoice: [{
  translation: "For the samurai, it must have been an easy place to defend.",
  before: "武士達にとって、守りやすい場所だった",
  after: "。",
  options: ["に違いありません", "ようにしました", "わけにはいきません", "ことになりました"],
  answer: 0,
  grammarKey: "tobira-5-10",
  explanation: "〜に違いない (polite: 〜に違いありません) shows strong certainty: \"must be ~\".",
}],
particle: [{
  text: "外国［と］の戦いなので、敵［から］取れる土地［が］なかったからです。",
  translation: "Because it was a war against a foreign country, …",
  explanation: "から marks who you get or take something from.",
}],
```

## 7. ユーザーの本棚に追加

`src/users.ts` の対象ユーザーの `articleIds` に新しい `id` を先頭に足す。
配列順がサイドバー表示順になる。

```ts
{
  id: "shaun",
  displayName: "Shaun",
  articleIds: ["professions-food", "professions-transport", "professions-daily", "growth"],
},
```

これを忘れると記事は `ARTICLES` にあってもサイドバーに出ない（初回の
ハマりどころ）。

## 8. ブラウザで確認

`npm run dev` で以下5タブすべてを見る:

| タブ | 見るところ |
|---|---|
| 記事 | ふりがな、注釈クリック、文末「▶ 訳」ボタン、語数・注釈数 |
| 単語リスト | `N/N 語` のカウント、注釈済み語が上位に来るか |
| 翻訳練習 | 全文がカード化される（`translations` のキー漏れがあると欠ける） |
| 単語クイズ | 選択肢とふりがな、`answer` の正誤 |
| 読解クイズ | 「解答を見る」で模範解答、「使う単語のヒント」でチップ |

エラーがなくても翻訳練習で文が欠けている場合は `translations` のキーが
本文と一致していない。本文からコピーし直す。

## 9. 命名規則

- `id`: `<series>-<slug>` の kebab-case（`professions-food`, `travel-onsen` など）。
- 動詞注釈: 品詞は `動詞（一段）`, `動詞（五段）`, `動詞（サ変）` を使い分ける。
- カタカナ職業（`シェフ`, `パティシエ`, `ウェイター`）は `reading` にも
  同じカタカナを入れる（kuromoji が読みを出さない場合の保険）。
